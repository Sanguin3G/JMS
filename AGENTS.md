# Codex working rules for JMS

Repository evidence is authoritative. External planning (for example, ChatGPT web / Sol high) supplies intent, not guaranteed facts about this checkout.

- Terra high is the sole implementation and documentation owner. Inspect before modifying; do not speculate into modernization.
- Use bounded, read-only Luna high specialists selectively (`@explore`, `@docs_researcher`, `@web_researcher`, `@technical_writer`). Escalate to Luna xhigh only when the work genuinely warrants it.
- The parent waits for specialists and consolidates their evidence before changing files. Specialists do not edit, stage, commit, or decide architecture.
- Protect unrelated user changes. Do not stage broadly, delete incidental files, or change remotes without explicit authority.
- When implementation begins, make semantic, purpose-scoped local commits and include proportionate tests with features. Never push automatically.
- Do not perform speculative dependency upgrades, framework migrations, refactors, or API/auth/database changes.
